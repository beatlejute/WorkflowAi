# Эталонная анатомия скила

Справочник по структуре и содержанию идеального скила workflow-ai.

## Обязательная структура директорий

```
skill-name/
├── SKILL.md              # Ядро: роль, маршрутизация, принципы
├── README.md             # Документация для людей
├── workflows/            # Пошаговые алгоритмы по типам тикетов
├── knowledge/            # Экспертные знания домена
├── algorithms/           # Формализованные методы принятия решений
└── templates/            # Шаблоны вывода
```

На уровне проекта, рядом со скилами (не внутри skill-name/): `shared/README.md` — индекс, `shared/module.md` — сами межскиловые модули (см. «Shared Knowledge» ниже).

## SKILL.md — обязательные секции

| Секция | Критерий качества |
|--------|-------------------|
| **Frontmatter** (name, description, ticket_prefix) | description 2-3 предложения, prefix уникален |
| **Роль** (делает / не делает) | Конкретно, без абстракций |
| **Маршрутизация** (тип → триггеры → воркфлоу) | Каждый тип → свой файл. **Только собственные типы** |
| **Загрузка знаний/алгоритмов/шаблонов** | Все файлы перечислены с условиями загрузки |
| **Принципы** (3-7) | Actionable, не декларативные |
| **Формат вывода** | Специфичен для домена |
| **Границы компетенции** | Перечислены смежные зоны с указанием куда направить |

## ⛔ Принцип изоляции скилов

Скилы НЕ знают о других скилах по имени. Используй: «любой скил проекта», generic ID (XXX-NNN).

**Изоляция от project-wide типов:** не хардкодить типы из `config.yaml:task_types`. Маршрутизация — по собственным типам скила, не по project-wide.

## Требования к качеству компонентов

| Компонент | Ключевые требования |
|-----------|--------------------|
| **Workflows** | Пронумерованные шаги, ссылки на knowledge/algorithms, чеклисты завершения |
| **Knowledge** | Таблицы/списки, маркер `<!-- РАСШИРЕНИЕ -->`, формулы явно, источники |
| **Algorithms** | Вход → алгоритм → выход, пороги числами, пример применения |
| **Templates** | Обязательные/опциональные поля, placeholder-подсказки, markdown |
| **README.md** | Название, структура, flow, как расширять |

## Shared Knowledge — межскиловые знания

Модуль нужен 2+ скилам → выносится в `skills/shared/` (`shared/README.md` — обязательный индекс: таблица `| Модуль | Описание | Используется в |`, `shared/module.md` — сами модули; см. дерево выше).

| Правило | Описание |
|---------|----------|
| **Критерий выноса** | Контент используется 2+ скилами с пересечением 70%+ |
| **Скилы — универсальные, shared — проектный** | Скилы переносятся между проектами as-is. Shared содержит проектно-специфичные знания |
| **Ссылка из скила — через glob, одна каноническая строка** | В таблице «Загрузка знаний» каждого скила — строка с модулем `.workflow/src/skills/shared/*` и условием: «**Перед началом работы** — если в проекте есть `.workflow/src/skills/shared/README.md`, прочитай этот индекс и загрузи модули, релевантные текущей задаче; отсутствие `shared/` — не блокер». Дословно эта формулировка (допустим только собственный триггер вместо «Перед началом работы»). Не хардкодить имена модулей и не перечислять примеры содержимого shared |
| **Path resolution — project-relative, не SKILL-relative** | Скилы могут быть подключены в проект как символические ссылки/junctions на canonical-каталог скилов. Если скил вычисляет путь к shared через `..` от собственной location (`<skill-dir>/../shared/`), на Windows symlinks/junctions это резолвится через realpath в canonical-каталог скилов, где `shared/` отсутствует (`shared/` живёт в проекте). Поэтому **всегда используй project-relative путь**: `.workflow/src/skills/shared/<file>` от корня проекта. Не пиши `../shared/<file>` в SKILL.md/workflow — это ломается под symlink-deployment |
| **Domain-контекст — в скиле** | Специфичная интерпретация shared-знаний остаётся в knowledge/workflows скила |

**Антипаттерны:** дублировать данные в knowledge/ нескольких скилов (вынести в shared/); хардкодить `.workflow/src/skills/shared/module.md` в SKILL.md (используй `.workflow/src/skills/shared/*` → проверить README); класть в shared/ knowledge одного скила (оставить в knowledge/ скила); вкладывать shared/ в конкретный скил (shared/ — на одном уровне со скилами).
