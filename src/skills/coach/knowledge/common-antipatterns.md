# Типичные антипаттерны в скилах

Чеклист проблем при аудите и ревью скилов.

| # | Категория | Антипаттерн | Как исправить |
|---|-----------|------------|---------------|
| S1 | Структурные | Осиротевшие файлы (не в SKILL.md) | Добавить в таблицу загрузки или удалить |
| S2 | Структурные | Битые ссылки | Создать файл или исправить ссылку |
| S3 | Структурные | Пустые директории | Заполнить или убрать |
| S4 | Структурные | Монолитный SKILL.md | Декомпозировать в воркфлоу |
| S5 | Структурные | Нет README | Создать по эталону |
| C1 | Содержание | Абстрактная роль | Описать роль, границы, зону ответственности |
| C2 | Содержание | Размытые принципы | Что делать, когда, как измерить |
| C3 | Содержание | Воркфлоу-декларация без шагов | Конкретные шаги, чеклисты, пороги |
| C4 | Содержание | Knowledge без структуры | Таблицы, заголовки, маркеры расширения |
| C5 | Содержание | Algorithm без формул | Числовые критерии, формулы, пороги |
| C6 | Содержание | Template без подсказок | Примеры и placeholder в каждое поле |
| B1 | Поведение | Выход за границы | Уточнить «Ты НЕ делаешь» |
| B2 | Поведение | Дублирование знаний | Вынести в один модуль, ссылаться |
| B3 | Поведение | Нет маршрута для типа | Добавить воркфлоу/маршрутизацию |
| B4 | Поведение | Игнорирование knowledge | Добавить ссылки в шагах воркфлоу |
| B5 | Поведение | Нет fallback | Правило «Если тип не определяется — ...» |
| I1 | Изоляция | Хардкод имён ролей/скилов | → «любой скил проекта», generic ID (XXX-NNN) |
| I2 | Изоляция | Примеры с конкретными ID ролей | → XXX-001, example-skill |
| I3 | Изоляция | Таблица ролей во Взаимодействии | → «Любой скил может создать тикет {PREFIX}-*» |
| I4 | Изоляция | Ссылки на инструменты других скилов | → «описаны в SKILL.md исполнителя» |
| I5 | Изоляция | Границы компетенции с именами | → «соответствующий скил проекта» |
| IC1 | Изоляция от конфигурации | Хардкод project-wide типов задач | Скил определяет подход по содержимому тикета |
| IC2 | Изоляция от конфигурации | Knowledge-дубликат конфига | Удалить, источник правды — конфиг |
| IC3 | Изоляция от конфигурации | Воркфлоу под каждый project-wide тип | Организовать по этапам работы или собственным типам |
| SC1 | Scope management | Scope creep через DoD | Запретить скилу исполнения создавать тикеты |
| SC2 | Scope management | Декомпозиция без scope-guard | Проверка «Включено/Исключено из scope» |
| SC3 | Scope management | Тикеты-сироты без parent_plan | Обязательно заполнять parent_plan |
| SC4 | Scope management | Каскадная декомпозиция | Только скилы декомпозиции создают тикеты |
| SC5 | Scope management | Горизонт за пределами плана | Future-задачи → рекомендации, не тикеты |
| SC6 | Scope management | Каскад исполнение→план→декомпозиция | 3 уровня защиты в скиле исполнения |
| SC7 | Scope management | Автодекомпозиция без human-approval | Только планы со `status: approved` |
| M1 | Масштабирование | Нет маркеров расширения | `<!-- РАСШИРЕНИЕ: ... -->` в конец |
| M2 | Масштабирование | Жёсткая привязка | Параметризовать или вынести в конфиг |
| M3 | Масштабирование | Нет инструкций по расширению | Секция «Как расширять» в README |

**Проверка (I):** grep по именам скилов и ролей текущего проекта (директории `.workflow/src/skills/`, префиксы из `config.yaml → task_types`) в файлах `.workflow/src/skills/<skill>/` каждого скила, кроме себя, → 0 результатов.
