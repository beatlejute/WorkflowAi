# Алгоритм: Оценка качества скила

## Вход

Путь к директории скила (`.workflow/src/skills/<name>/`). Результаты `node .workflow/src/scripts/check-rails-graph.js --skill <name>` и `algorithms/rails-compliance.md` (структурная часть).

## Алгоритм

**Предусловие — скил на рельсах.** Нет валидного графа в `SKILL.md` или нет `rails.yaml` → итог **POOR (0–39)** независимо от остальных категорий, finding CRITICAL «скил не на рельсах», рекомендация CONVERT. Остальные категории всё равно считаются — они станут планом конверсии.

Оцени скил по 5 категориям. Каждая категория — от 0 до 20 баллов. Итого максимум — 100.

| Категория (макс 20) | Критерий | Баллы |
|----------------------|----------|-------|
| 1. Структура | SKILL.md существует, frontmatter с `rails: rails.yaml`, граф ядра валиден (checker) | 4 |
| 1. Структура | README.md существует и описывает структуру и flow по этапам | 3 |
| 1. Структура | workflows/ содержит фрагмент для каждой ветки из Q-узла маршрутизации | 4 |
| 1. Структура | rails.yaml валиден, у каждого гарда есть тест в tests/rails/ | 4 |
| 1. Структура | knowledge/ содержит минимум 2 модуля | 2 |
| 1. Структура | algorithms/ ≥ 1 алгоритм, templates/ ≥ 1 шаблон | 3 |
| 2. Полнота ядра | Роль описана конкретно в E/R этапа 0 (делает / не делает) | 4 |
| 2. Полнота ядра | Маршрутизация полная: Q-узел с триггерами, ребро на каждую ветку, fallback | 4 |
| 2. Полнота ядра | Каждый файл knowledge/ загружается узлом с условием | 3 |
| 2. Полнота ядра | Каждый файл algorithms/ и templates/ упомянут узлом | 3 |
| 2. Полнота ядра | Правила (R-узлы) конкретны и actionable, 3–7 штук, с датой и ценой инцидента где применимо | 3 |
| 2. Полнота ядра | Этап отчёта: формат вывода и обязательные строки специфицированы | 2 |
| 2. Полнота ядра | Границы компетенции определены | 1 |
| 3. Качество фрагментов | Шаги — S-узлы с глаголами, лейблы ≥ 25 символов | 5 |
| 3. Качество фрагментов | Ссылки на knowledge/algorithms в лейблах там, где нужны данные | 5 |
| 3. Качество фрагментов | Гейты завершения с потолком; гейт перед каждым необратимым действием | 5 |
| 3. Качество фрагментов | Нет дублирования между ветками и прозы, дублирующей узлы | 5 |
| 4. Качество знаний и алгоритмов | Knowledge структурирован (таблицы, категории), без правил ⛔/⚠️, отсутствующих в узлах | 5 |
| 4. Качество знаний и алгоритмов | Маркеры расширения присутствуют | 3 |
| 4. Качество знаний и алгоритмов | Algorithms формализованы (формулы, пороги) | 5 |
| 4. Качество знаний и алгоритмов | Есть примеры применения | 4 |
| 4. Качество знаний и алгоритмов | Вход/выход алгоритмов определён | 3 |
| 5. Связность, консистентность, изоляция | Все ссылки из узлов ведут на существующие файлы | 4 |
| 5. Связность, консистентность, изоляция | Нет осиротевших файлов knowledge/algorithms/templates | 4 |
| 5. Связность, консистентность, изоляция | Терминология единообразна между ядром, фрагментами и справочниками | 4 |
| 5. Связность, консистентность, изоляция | **Изоляция:** нет хардкода имён других скилов/ролей (grep на имена ролей = 0) | 4 |
| 5. Связность, консистентность, изоляция | Бюджет: ядро ≤ 400 строк, ядро + фрагмент + справочники ≤ 800 | 4 |

Балл соответствия рельсам (структурный + поведенческий) считается отдельно по `algorithms/rails-compliance.md` и приводится в отчёте рядом.

## Выход

| Балл | Оценка | Рекомендация |
|------|--------|-------------|
| 80–100 | **EXCELLENT** | Скил готов к работе, мелкие улучшения |
| 60–79 | **GOOD** | Работоспособен, но есть существенные пробелы |
| 40–59 | **NEEDS_WORK** | Требуется серьёзная доработка |
| 0–39 | **POOR** | Фундаментальные проблемы или скил не на рельсах — CONVERT или пересоздание |

## Пример

`example-skill`: структура 20 + полнота ядра 20 + фрагменты 15 (−5 гейт П3 без потолка) + знания 17 (−3 нет примеров в algorithms) + связность 20 = **92/100 — EXCELLENT**; соответствие рельсам по `rails-compliance.md` — 78 DRIFT (гард `run_tests` без теста, узел P3S1 с повторными отказами).
