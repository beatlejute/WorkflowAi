# Воркфлоу: TEST — Авторство тест-кейса регрессионного теста скила

> **Активирован.** Воркфлоу обязателен после каждой правки скила (см. SKILL.md → «Обязательный шаг: Тест»).

Воркфлоу описывает, как коуч создаёт регрессионный тест для скила при обнаружении инцидента.

**Знания:** загрузи `knowledge/test-authorship.md` перед выполнением шагов.

## Шаги 1–5: Подготовительный этап

### Шаг 1. CHG-запись не создаётся

Тест-кейс — фиксация инцидента, не изменение скила: **не создавай** запись в `applied_changes[]` бэклога; инцидент фиксируется полем `origin` в YAML кейса.

### Шаг 2. Получить ID тест-кейса

Вызови из корня проекта `node .workflow/src/scripts/get-next-test-id.js --skill <имя-скила>` → ID `TC-<SKILL>-NNN`; используй именно его, не генерируй вручную.

### Шаг 3. Выбор слоёв (L0 / L1 / L2)

Логика выбора — целиком в `knowledge/test-authorship.md`, раздел «Дерево выбора слоя» (правило минимума: сомневаешься между L0 и L1 — выбирай L0; L2 — только если L0/L1 физически неприменимы).

### Шаг 4. Построить фикстуру

Правила минимизации фикстуры — целиком в `knowledge/test-authorship.md`, раздел «Минимизация фикстуры».

Сохрани фикстуру в `tests/fixtures/` скила.

### Шаг 5. Написать YAML тест-кейса и проверить `index.yaml`

1. Создай файл `tests/cases/<ID>.yaml` по структуре существующих кейсов в `tests/cases/`.
2. В поле `origin` укажи ID инцидента (CHG или ссылку на артефакт).
3. Проверь `tests/index.yaml` скила:
   - Содержит ли он актуальный список `target_agents[]`?
   - Если в `pipeline.yaml` появились новые модели — добавь их. Удаление/сокращение — только по явному согласию стейкхолдера (см. `knowledge/test-authorship.md` §5).
4. Добавь запись о новом кейсе в секцию `cases:` файла `tests/index.yaml`.

## Шаги 6–9: Исполнительный этап

### Шаг 6. Прогон тестов

Запусти из корня проекта `node .workflow/src/scripts/run-skill-tests.js --skill <name> --relevant <TC-NNN>`, где `<name>` — имя скила, `<TC-NNN>` — ID тест-кейса, созданного на шаге 2.

### Шаг 7. Проверка verdict из `---RESULT---`

Прочитай поле `verdict` в блоке `---RESULT---` вывода скрипта:

- `ready_for_user_review` → перейти к шагу 8.
- `regression_detected` / `relevant_case_failed` / `no_baseline_failures` → доработать скил или тест, вернуться к шагу 6.

### Шаг 8. Сообщить пользователю

Сообщи пользователю:

- **Список затронутых файлов:** `SKILL.md` и/или `workflows/`, `tests/cases/{id}.yaml`, `tests/index.yaml`, `tests/cases/{id}/current/`
- **Verdict** из шага 7.

**Остановиться.** Коуч не делает ничего сверх этого — коммит на стороне пользователя (шаг 9).

### Шаг 9. Коммит делает исключительно пользователь

Git-запрет — SKILL.md «⛔ Коуч не выполняет git-операции»; в `applied_changes[]` не пишем — история правки в git (скил + тест одним коммитом пользователя).
