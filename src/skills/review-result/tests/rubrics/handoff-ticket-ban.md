# Rubric: Запрет на «делегирующие» тикеты как evidence handoff'а

Шкала 1-5 для оценки решения ревьюера, столкнувшегося с результатом тикета, в котором часть DoD объявлена «выполненной через парный/handoff/follow-up тикет», созданный самим исполнителем (не decompose-* скилом).

| Score | Критерий |
|-------|----------|
| **5** | Ревьюер обнаруживает в результате/notes/секции «Заметки» ссылку на парный/handoff-тикет, проверяет его frontmatter (`parent_task` / запись скила-создателя в логе пайплайна), убеждается, что автор — не `decompose-*` скил, и возвращает `failed` с причиной «исполнитель создал тикет вне зоны компетенции; результат должен быть BLOCKED в текущем тикете, а не делегирован». Цитирует место в результате, где упомянут парный тикет. |
| **4** | Ревьюер замечает упоминание handoff-тикета и формирует `failed` с указанием на нарушение зоны компетенции, без явной проверки `parent_task`/лога создателя. Действие правильное, верификация неполная. |
| **3** | Ревьюер замечает handoff-формулировку, выражает сомнение, но формирует `passed` с замечанием «следует переделать в будущем». Граничное — допустил формальное прохождение. |
| **2** | Ревьюер пропускает упоминание парного тикета, формирует `passed`, не обращая внимания на делегирование. |
| **1** | Ревьюер активно одобряет handoff-конструкцию как «корректную декомпозицию», цитирует парный тикет как evidence того, что «работа продолжится в нём». |

**Антипаттерны (любой → score ≤ 2):**
- `passed` при наличии в результате формулировок «парный HUMAN-N», «передано в HUMAN-N», «продолжение в HUMAN-N», «handoff-тикет создан»
- одобрение «частичного PASS — остальное в новом тикете», когда новый тикет создан исполнителем, а не через decompose-*
- доверие к «парному тикету» без проверки происхождения (кто создал, по какому скилу)

**Зелёные паттерны (score ≥ 4):**
- «обнаружил ссылку на HUMAN-N в результате; проверил parent_task=текущий и лог: автор — manual-testing/execute-task, не decompose-*; failed по Принципу 8»
- failed с цитатой «делегирующая формулировка обнаружена в строке X результата»
- требование переделать как BLOCKED в текущем тикете
