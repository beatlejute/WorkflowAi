# Шкала оценки пункта DoD по evidence

Одна шкала для пунктов DoD вида `prose` и `visual` тикета с `dod_format: 2`. Вопрос шкалы: насколько собранные evidence (для `visual` — приложенные изображения) подтверждают пункт DoD.

Шкалу читает `scripts/prepare-review.js`: пять строк таблицы (`rubricLevels`, `src/lib/rubric-levels.mjs`) становятся уровнями вопроса модели стадии ревью, текст пункта DoD — текстом вопроса (у `visual` — с путями его изображений). Модель получает тексты уровней, вопрос и данные evidence — этот файл целиком она не видит. Поэтому всё, от чего зависит балл, записано в самих строках таблицы; проза вокруг таблицы балл не назначает. Строк вида `| N | … |` с номером 1–5 вне таблицы шкалы в файле быть не должно: конвертер берёт для каждого уровня первую такую строку файла.

Данные evidence для модели собирает `scripts/prepare-review.js` из файла `.workflow/state/evidence/<TICKET-ID>.json`: проверки пунктов DoD с выводом, фрагменты исходника по ссылкам `file:line` из `source_refs`, дифф по «Изменённым файлам» с пометкой усечения, изображения пунктов `visual`. Раздела Result тикета в данных нет.

## Шкала

Уровни — лестница по одному признаку: что факты evidence показывают о пункте DoD. Факт — вывод проверки, строки диффа или исходника, изображение. Слова о выполнении пункта («сделано», «проверено») без такого факта балл не повышают: пилот судьи 2026-09-24 показал, что модель принимает заявление тикета за факт, если доказательства в контексте нет, — правило записано в строке уровня 2, которую модель видит. Строку диффа тикет пишет сам, поэтому строка, которая утверждает результат о другом объекте, фактом об этом объекте не становится, а пункт о соответствии или полноте подтверждён, только когда в evidence есть обе стороны сравнения, — правила записаны в строках уровней 2–5. Инцидент 2026-09-29: пункт о полноте документа относительно хранимых данных получил уровень 5 по одному диффу документа, без строк исходника хранилища, а пункт о размерах изображений — по таблице «Измерено» и коду теста, которые добавил тот же тикет, без вывода запуска теста; исполнитель в тикете прямо писал, что так строки «становятся фактом репозитория».

| Балл | Описание |
|------|----------|
| 1 | Факт evidence опровергает пункт DoD или его часть: вывод проверки, строки диффа или исходника, изображение показывают не то, что утверждает пункт. |
| 2 | Evidence о пункте DoD молчит: ни один факт — вывод проверки, строки диффа или исходника, изображение — его не подтверждает и не опровергает; слова о выполнении пункта («сделано», «проверено») без такого факта — тоже молчание. Строка диффа или исходника, которая сама утверждает результат о другом объекте («измерено», «проверено», «описывает всё», «других нет»), — факт о своём тексте, а не об этом объекте; код теста без вывода его запуска — факт о тесте, а не о результате; без вывода проверки, строк исходника или изображения самого объекта это тоже молчание. |
| 3 | Факты evidence подтверждают только часть пункта DoD, об остальной части evidence молчит. Пункт о соответствии или полноте относительно другого объекта (кода, данных, требований, файла), строк или вывода которого в evidence нет, — не выше этого уровня. |
| 4 | Факты evidence подтверждают пункт DoD целиком, но хотя бы одна его часть видна в них не прямо, а следует косвенно, выводом из увиденного. У пункта о соответствии или полноте обе стороны сравнения есть в фактах evidence: косвенным бывает только вывод об их совпадении, а не вторая сторона; строка, которая сама утверждает результат, и код теста без вывода его запуска вторую сторону не заменяют. |
| 5 | Каждая часть пункта DoD прямо видна в фактах evidence; у пункта о соответствии или полноте в них видны обе стороны сравнения. |

## Проход

Уровень 4 — первый, на котором пункт DoD подтверждён целиком. `scripts/apply-review.js` засчитывает пункт при уровне не ниже `pass_level` (4, если в `model_io.options` стадии порог не задан) и уверенности модели не ниже `min_confidence` или без уверенности: агент, который её не сообщает, отвечает только баллом.
