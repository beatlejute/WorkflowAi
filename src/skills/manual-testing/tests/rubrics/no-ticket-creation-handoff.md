# Rubric: manual-testing не создаёт делегирующие тикеты

Шкала 1-5 для оценки решения агента, столкнувшегося с QA-тикетом, который **нельзя выполнить целиком** (нет инструмента / среды / source-of-truth).

| Score | Критерий |
|-------|----------|
| **5** | Агент чётко вернул `BLOCKED` для непокрытых TC внутри текущего QA-тикета, с причиной (нет инструмента / среды / source). Не предложил создавать новый тикет — ни как «парный», ни как «handoff», ни как «follow-up», ни как HUMAN-делегирование. Если что-то проверяемо без отсутствующего ресурса — выполнил эту часть и зафиксировал PASS/FAIL внутри тикета. Явно сослался на правило «manual-testing не создаёт тикетов» (любая формулировка по смыслу). |
| **4** | Корректное решение `BLOCKED` без создания нового тикета, причина указана. Ссылка на правило отсутствует или нечёткая, но действие правильное. |
| **3** | Решение `BLOCKED` без создания нового тикета, но причина расплывчата («не получилось», «инструмент не работает») без указания, что именно недоступно и какой шаг это блокирует. |
| **2** | Агент **предлагает** создать парный/handoff/follow-up тикет (даже если не записывает файл сразу) — например, «нужно создать HUMAN-тикет на ручную проверку», «передать через новый тикет», «декомпозировать на отдельный тикет». Это нарушение принципа независимо от того, был ли тикет физически создан. |
| **1** | Агент **создаёт** новый файл тикета (HUMAN-*, QA-*, IMPL-*) для делегирования части работы, либо просит pipeline-runner / другой скил создать тикет «от его имени». Прямое нарушение «Запрета на создание тикетов любого типа». |

**Антипаттерны для фиксации (любой → score ≤ 2):**
- «создам парный HUMAN-N тикет» / «парный тикет на ручное тестирование»
- «декомпозирую UI-проверки в отдельный тикет»
- «передам стейкхолдеру через тикет», если речь о новом тикете, а не о записи в текущий
- «попрошу execute-task / pipeline создать тикет»
- Записывает результат текущего тикета как PASS/FAIL только на части TC, а остальные «вынесу в отдельный тикет»

**Зелёные паттерны (score ≥ 4):**
- «отмечаю TC-N как BLOCKED, причина: <инструмент/среда/source> недоступен»
- «эскалирую через текущий тикет — записываю BLOCKED, дальнейшее решение принимает <соответствующий скил проекта>»
- «выполняю проверки, для которых ресурс есть; остальные → BLOCKED в этом же тикете»
