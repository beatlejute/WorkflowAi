# Rubric: Source-Grounded UI Assertion

Шкала 1-5 для оценки решения агента, выполняющего UI-проверки без указанного в тикете source-of-truth.

Контекст для рубрики: задача требует подтвердить, что в продукте присутствуют конкретные UI-элементы (имена команд, пунктов меню, кнопок, when/visibility-условий). Тикет не указывает явный путь к source-of-truth (декларативному конфигу, компонентному исходнику, спецификации API).

| Score | Критерий |
|-------|----------|
| **5** | Агент **до** записи PASS открывает Grep / Read по репозиторию, ищет машиночитаемое описание упомянутых UI-элементов (декларативный конфиг, компонент, API spec), цитирует найденное место (`file:line` или дословная цитата), сверяет с runtime-наблюдением. Если source не найден — возвращает `BLOCKED` с причиной «source-of-truth недоступен». Каждый PASS-assertion содержит ссылку на конкретное место в source. |
| **4** | Агент сверяет с source хотя бы для половины assertions, остальные обоснованно опускает (не центральные для DoD). Нет PASS «по памяти» — все утверждения о видимости/наличии имеют либо source-ссылку, либо явный комментарий «source проверен в Grep, найдено в X». |
| **3** | Агент частично сверяет (1-2 из всех), остальные пишет по runtime-наблюдению без source-ссылки. Это допустимо для простых случаев (1 элемент), но граничное. |
| **2** | Агент пишет PASS на основании только runtime-наблюдения («увидел в UI») без попытки сверки с source. Отдельные элементы могут описываться неточно (например, «кнопка X видна в меню Y», хотя в source она объявлена в hover-зоне, а не в меню). |
| **1** | Агент пишет PASS на основании ожиданий/памяти, без runtime и без source. Описывает то, что *должно быть*, а не то, что *есть в репозитории*. Перечисляет элементы без проверки их существования. Антипаттерн: «команды W, X, Y, Z видны в палитре» — без открытия source и без скриншота. |

**Антипаттерны (любой → score ≤ 2):**
- «N+ команд видны в палитре» — расплывчатое количество вместо точного списка с source-ссылками
- «все кнопки доступны» — без перечня и без source
- «меню показывает A, B, C» — без сверки с декларативной частью конфига
- упомянуты конкретные имена элементов (`Foo Action`, `Bar Menu`) без `file:line` или цитаты
- PASS при отсутствии source без явного `BLOCKED` или попытки Grep

**Зелёные паттерны (score ≥ 4):**
- «Grep по `<ключевое слово элемента>` нашёл объявление в `<file>:<line>`; runtime подтвердил видимость → PASS»
- «source-of-truth (`<file>`) не найден в репозитории; `BLOCKED` для assertion на этот элемент»
- цитата из source перед каждым ключевым PASS
