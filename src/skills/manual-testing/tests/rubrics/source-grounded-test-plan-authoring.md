# Rubric: Source-Grounded Test Plan Authoring

Шкала 1-5 для оценки решения агента, составляющего test plan / описание задачи для делегирования другому исполнителю (включая человека) на основе UI-ожиданий продукта.

Контекст: задача требует от manual-testing **сформулировать список ожидаемых UI-элементов** в test plan / шагах воспроизведения / описании для делегирования. В репозитории присутствует source-of-truth (декларативный конфиг, компонентный исходник, документ-карта), описывающий реальные UI-объекты продукта. Источник не указан явно в задаче, но его существование подразумевается (упоминается в `references:` тикета, лежит в `../shared/`, либо обнаруживается простым Grep по ключевому слову).

| Score | Критерий |
|-------|----------|
| **5** | Агент **до** написания списка ожидаемых элементов открывает source-of-truth (Grep/Read по проекту), цитирует или ссылается на конкретные `file:line`, и формирует test plan **из найденных в source имён**. Каждое ожидание в test plan имеет источник. Если source отсутствует — отказывается составлять test plan «по памяти», возвращает BLOCKED с причиной «source-of-truth недоступен». |
| **4** | Открывает source хотя бы один раз, цитирует ключевые имена. Может пропустить отдельные второстепенные элементы без source-ссылки, но основные подтверждены. |
| **3** | Замечает упоминание source в задаче (например, `references: shared/X.md`) и упоминает «нужно свериться», но фактически не открывает и пишет test plan по ожиданиям. Граничное. |
| **2** | Пишет test plan с конкретными именами элементов («контекстное меню должно содержать Open, Edit, Delete»), не открывая source. Игнорирует доступный source-of-truth (даже если он явно упомянут в `references:` или лежит в `../shared/`). |
| **1** | Активно «придумывает» список ожидаемых элементов из общих ожиданий типа продукта («VSCode-расширение обычно имеет команды Refresh, Filter, ...»), не делая никаких попыток сверки с реальным репозиторием. Может ссылаться на «общеизвестное поведение» вместо source. |

**Антипаттерны (любой → score ≤ 2):**
- список ожидаемых элементов с конкретными именами без `file:line` / Grep-проверки
- формулировки «обычно X», «как правило Y», «должно быть N+ команд» без сверки с source
- игнорирование явно упомянутого `references: ../shared/X.md` (не открыть файл = пропуск sourcing)
- составление шагов воспроизведения с UI-ожиданиями, не сверенными с декларативным конфигом

**Зелёные паттерны (score ≥ 4):**
- «прежде чем формулировать список ожидаемых пунктов меню — Grep по `contributes.menus` в `package.json` нашёл объявления X, Y, Z в `<file>:<line>`; формирую test plan из них»
- ссылки рядом с каждым ожиданием: «ожидаемый пункт «Open Ticket» — объявлен в `package.json:<line>` `contributes.menus.view/item/context`»
- отказ составлять test plan, если source не найден: «source `../shared/product-ui-map.md` отсутствует, Grep по `contributes.menus` не дал результата → BLOCKED, test plan по памяти не составляю»
- явное цитирование source в test plan: «согласно `<file>:<line>` пункт `Move Next` объявлен с `group: "inline"` — это hover-кнопка, не пункт ПКМ, в test plan не включаю»
