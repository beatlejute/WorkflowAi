## Анализ тикета и план действий

### Ключевое наблюдение

Тикет содержит **встроенное противоречие между скопом и условием среды:**

> «Все 5 инвариантов проверены в живом runtime» — **DoD**
> «десктоп-приложение недоступно... Запустить приложение физически невозможно» — **Условие среды**

Все 5 инвариантов — строго UI-observable: видимость кнопок, пункты контекстного меню, отсутствие warning'ов в UI-панели, видимость команд в палитре, рендеринг welcome-view. Ни один из них не выражается через ФС, структуру файла или данные — только через наблюдение живого интерфейса.

---

### Исходы для каждого TC

| TC | Инвариант | Исход | Причина |
|----|-----------|-------|---------|
| I-1 | Title bar кнопки видны во всех секциях | **BLOCKED** | Требует живого рендеринга VSCode + расширения |
| I-2 | Контекстное меню при ПКМ — ожидаемые пункты | **BLOCKED** | Требует UI-взаимодействия (ПКМ) в живом runtime |
| I-3 | Нет warning'ов о неопределённых command-ссылках | **BLOCKED** | Warning'и в Extensions-панели — UI-observable, не FS |
| I-4 | Команды основной категории видны в палитре | **BLOCKED** | Палитра команд — только в живом VSCode |
| I-5 | Welcome-view при отсутствии конфигурации | **BLOCKED** | Рендеринг view — только в живом runtime |

Проверка манифеста (`package.json`/`contributes.*`) даёт **source-of-truth для ожидаемых значений**, но не заменяет runtime: манифест описывает декларацию, а инварианты требуют подтверждения рендеринга. `PASS` по манифесту без runtime = фабрикованный результат (принцип 10).

---

### Что записываю в тикет

**Все 5 TC → BLOCKED** с единой причиной:

```
BLOCKED — UI runtime недоступен в текущей среде исполнения (Sandbox без
графической оболочки и установленного VSCode). Проверка UI-observable
инвариантов (рендеринг, интерактивность, отображение панелей) физически
невозможна. Манифест расширения присутствует в репозитории и может быть
использован как source-of-truth для ожидаемых значений при повторном
выполнении тикета в рабочей среде.
```

DoD тикета не может быть закрыт: `[ ]` для всех 5 пунктов с пометкой «BLOCKED — runtime недоступен».

---

### Что НЕ делаю

- **Не читаю манифест и не записываю PASS** — это нарушение принципа «Source-Grounded UI Assertion»: manifest assertion ≠ runtime assertion для UI-observable инвариантов
- **Не запускаю существующие автотесты** — антипаттерн подмены ручной проверки (явно запрещён)
- **Не создаю дочерние тикеты** — запрещено; решение об эскалации принимает decompose-скил

---

### Следующие шаги (предложение для ответственного скила)

Тикет завершается как **BLOCKED**. Возможные пути разблокировки (на усмотрение pipeline):

1. **Перевыполнить тикет в среде с GUI** — Sandbox с установленным VSCode и расширением (настройка: `knowledge/sandbox-core.md`)
2. **Разделить скоп** — если часть инвариантов можно выразить через не-UI проверки (например, I-3 частично через DevTools-лог), это отдельный тикет с переопределённым DoD — решение за decompose-скилом
3. **Обновить DoD тикета** — если намерение было проверить только декларативный манифест (без runtime), DoD должен это явно отражать, и тип тикета — не QA-regression
