Смотрю на ситуацию и формирую план.

**Диагноз: среда заблокирована для всех 5 TC**

Условие тикета явно сообщает: *«запустить приложение и наблюдать UI физически невозможно»*. Все 5 инвариантов — UI-наблюдаемые (рендеринг, реакция на действия, видимость элементов). Значит, манифест из репозитория может дать только декларативный контракт, но не подтвердить runtime-рендеринг.

---

## Шаги

**1. Загрузить обязательные модули:**
- `algorithms/blocked-tool-strategy.md` — дерево решений при блокировке инструмента
- `../shared/README.md` + релевантные модули карты UI (ticket упоминает, что shared присутствует)

**2. Source-check манифеста (частичный evidence)**

Для каждого инварианта — прочитать source-of-truth (манифест расширения, declarative config) и зафиксировать, что там *задекларировано*. Это не заменяет runtime-проверку, но даёт контекст и исключает «BLOCKED без попытки».

**3. Исходы для всех 5 TC**

| TC | Инвариант | Исход | Причина |
|----|-----------|-------|---------|
| I-1 | Title bar кнопки видны | **BLOCKED** | UI runtime недоступен: нет графической оболочки |
| I-2 | Контекстное меню ПКМ | **BLOCKED** | То же; ПКМ-взаимодействие требует live shell |
| I-3 | Нет warning'ов в панели расширений | **BLOCKED** | То же; панель расширений — live UI |
| I-4 | Команды видны в палитре | **BLOCKED** | То же; палитра команд — live UI |
| I-5 | Welcome-view при отсутствии конфига | **BLOCKED** | То же; welcome-view — live render |

Для I-3 и I-4 возможен частичный source-check: проверить, что команды/contributions задекларированы в манифесте. Но это даёт только `manifest: declared`, не `runtime: rendered` — в evidence явно указать разницу.

**4. Что записывается в тикет**

Для каждого TC — секция по формату `templates/bug-report.md` с исходом **BLOCKED**:
- Причина: *«UI runtime недоступен в текущей среде исполнения — отсутствует графическая оболочка и установленный runtime VSCode»*
- Partial evidence (если source-check выполнен): ссылка на строку манифеста + дословная цитата задекларированного элемента
- Что необходимо для разблокировки: Sandbox с установленным VSCode и расширением

Итоговый отчёт о сессии по `templates/test-session-report.md`: 0 PASS / 0 FAIL / 5 BLOCKED.

DoD тикета не выполнен — ни один критерий (`проверены в живом runtime`, `evidence: скриншоты + a11y assertions`) не достигнут. Пункты остаются `[ ]` с пояснением о причине блокировки.

**5. Следующие шаги (предложение ответственному скилу)**

QA-тикет фиксирует BLOCKED и на этом завершает работу — создание новых тикетов запрещено. Ответственный скил проекта принимает решение:
- настроить Sandbox с установленным VSCode + расширением (предпочтительно — позволяет выполнить все 5 TC в следующей итерации)
- или принять BLOCKED как осознанное решение (если среда настройки экономически нецелесообразна для этого sweep'а)
