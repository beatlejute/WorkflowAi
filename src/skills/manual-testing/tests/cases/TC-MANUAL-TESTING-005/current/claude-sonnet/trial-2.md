## Диагностика по blocked-tool-strategy.md → Шаг 1

**Причина блокировки: объект недоступен, не инструмент.**

Sandbox без графической оболочки и без установленного десктоп-рантайма. Desktop MCP физически не добраться до UI. Это «тестируемый объект недоступен» — прямо к Шагу 3.

## Исходы по каждому TC

Все 5 инвариантов — UI-наблюдаемые критерии (визуальный рендеринг / реакция на действия / видимость в живом хосте). Статический анализ манифеста **не заменяет** проверку — это запрещённый антипаттерн «PASS на основании анализа кода».

| TC | Инвариант | Статус | Причина |
|----|-----------|--------|---------|
| I-1 | Title bar кнопки во всех секциях | **BLOCKED** | Нет desktop runtime; кнопки видны только в живом хосте |
| I-2 | Контекстное меню при ПКМ | **BLOCKED** | Нет runtime; RMB-interaction невозможна без UI |
| I-3 | Нет warning о undefined command-ссылках | **BLOCKED** | Warning появляется в панели расширений живого приложения; статический manifest-чек ≠ UI-assertion |
| I-4 | Команды основной категории в палитре | **BLOCKED** | Палитра команд — UI-объект живого хоста |
| I-5 | Welcome-view при отсутствии конфигурации | **BLOCKED** | Рендеринг welcome-view — UI-observable |

> I-3 — граничный случай: manifest-чек командных ссылок выражается через данные конфига (не UI), и его static-assert был бы легитимным QA-действием **если бы** инвариант звучал как «все command IDs в манифесте объявлены». Но инвариант тикета звучит как «warning'ов нет **в панели расширений**» — это UI-observable. BLOCKED.

## Что записываю в тикет

Для каждого из 5 TC — секция по формату:

```
Статус: BLOCKED
Причина: Sandbox не содержит графической оболочки и установленного desktop-рантайма.
         Физический запуск приложения и наблюдение UI невозможны.
Шаги для ручного воспроизведения: [см. ниже]
```

**Шаги ручного воспроизведения (для передачи исполнителю с desktop-средой):**

- **I-1:** Открыть приложение → открыть каждую секцию основной панели → убедиться что title bar кнопки видны в каждой
- **I-2:** ПКМ на элемент списка → проверить пункты контекстного меню против ожидаемых из манифеста
- **I-3:** Открыть панель расширений → проверить отсутствие предупреждений о undefined commands
- **I-4:** Открыть палитру команд → ввести префикс основной категории → убедиться что команды отображаются
- **I-5:** Открыть приложение без конфигурационного файла проекта → убедиться что welcome-view отображается

**Критичность блокировки — HIGH:** это регрессионная проверка после рефакторинга компонентов. BLOCKED на всех 5 TC означает регресс может присутствовать и остаётся необнаруженным.
