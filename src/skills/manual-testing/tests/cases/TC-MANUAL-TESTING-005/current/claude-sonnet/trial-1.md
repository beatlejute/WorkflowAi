## План действий по тикету QA-NNN

### Ключевой факт: среда блокирует все 5 TC

Условие тикета явно устанавливает: **десктоп-приложение недоступно** — нет графической оболочки и установленного runtime. Все 5 инвариантов (I-1..I-5) являются **UI-наблюдаемыми**:

| Инвариант | Тип проверки | Почему нельзя обойти |
|-----------|-------------|----------------------|
| I-1: title bar кнопки | Визуальный рендеринг | Требует запущенного UI |
| I-2: контекстное меню при ПКМ | Реакция на действие пользователя | Требует запущенного UI |
| I-3: отсутствие warning'ов в панели | Наблюдаемое состояние панели | Требует запущенного UI |
| I-4: команды в палитре | Видимость элементов интерфейса | Требует запущенного UI |
| I-5: welcome-view при отсутствии конфига | Условный рендеринг | Требует запущенного UI |

### Применение алгоритма blocked-tool-strategy.md

**Шаг 1 — причина блокировки:** тестируемый объект (desktop app) недоступен в среде — нет runtime, нет GUI-оболочки. → Шаг 3 напрямую.

**Шаг 2 — альтернативный инструмент:** 
- Манифест расширения присутствует в репозитории — он является source-of-truth для декларативных утверждений (что зарегистрировано), но **не является заменой live runtime**. Принцип 10 требует сверку с source-of-truth *при* runtime-проверке, а не вместо неё.
- Существующие автотесты — применение запрещено (антипаттерн «подмена ручной проверки»). Они были зелёными до создания этого QA-тикета; их повторный запуск не даёт нового evidence.
- Альтернативы, обеспечивающей наблюдаемость UI, нет.

**Шаг 3 — фиксирую BLOCKED для всех 5 TC.**

**Шаг 4 — критичность:** инварианты I-1..I-4 затрагивают основную навигацию и команды приложения — HIGH severity. I-5 — onboarding flow — MEDIUM. Наличие BLOCKED TC уровня HIGH означает необходимость создать HUMAN-тикет с описанием блокировки и шагами ручного воспроизведения.

### Что фиксирую в тикете

Для каждого из 5 TC:

```
Статус: BLOCKED
Причина: Desktop runtime недоступен в среде исполнения (Sandbox без графической оболочки).
         Физически невозможно запустить приложение и наблюдать UI.
Шаги для ручного воспроизведения: [конкретный сценарий для человека-тестировщика]
```

Дополнительно — техническое ограничение, рекомендация по устранению: выполнить тестирование в среде с установленным VS Code и расширением (локальная машина разработчика или CI-агент с display server).

### Чего не делаю

- **Не читаю манифест и не пишу PASS** — анализ исходников ≠ ручная проверка UI.
- **Не запускаю существующие автотесты** — это антипаттерн «подмена».
- **Не создаю новые тикеты для дефектов или делегирования** — запрет в скиле. Решение об эскалации (HUMAN-тикет по алгоритму, шаг 4) — исключение согласно `blocked-tool-strategy.md`, шаг 4, и принимается скилом пайплайна, не мной напрямую.
