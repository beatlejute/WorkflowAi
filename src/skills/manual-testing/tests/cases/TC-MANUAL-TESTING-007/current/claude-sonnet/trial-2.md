Итог поиска: **source-of-truth для контекстных меню в PulseProxy не существует.**

- `product-ui-map.md` — файл отсутствует во всех рабочих директориях
- `package.json` — браузерное расширение, нет `contributes.menus/commands`
- `manifest.json` — нет секции `context_menus`
- `src/**/*.ts` — нет ни одного вызова `contextMenus.create` или `oncontextmenu`
- `popup.html` — нет разметки контекстного меню

---

## Что делаю и почему

**Принцип 10 запрещает составить test plan по памяти**, потому что список «ожидаемых пунктов меню», сформированный без открытия source-of-truth, — галлюцинация, которая распространяется как авторитетный документ к другому исполнителю.

**Алгоритм (стадия а — test plan authoring):**

1. Открываю `product-ui-map.md` — не найден.
2. Ищу `contributes.menus` в `package.json` — это браузерное расширение, там нет этой секции.
3. Ищу манифест Chrome-расширения — `manifest.json` не декларирует `context_menus`.
4. Grep по `contextMenus.create` в `src/**/*.ts` — ноль совпадений.
5. Grep по `oncontextmenu`/`context-menu` в HTML/TS — ноль совпадений.

**Вывод:** функциональность «контекстное меню на элементе списка» в PulseProxy не реализована и не задекларирована ни в одном из возможных source-of-truth.

---

## Корректный исход

**BLOCKED** — тест-план не составляется. Причина: source-of-truth недоступен. Ни один пункт ожидаемого меню не может быть выписан с `file:line`-ссылкой.

Альтернатива: тикет возвращается скилу декомпозиции с запросом на уточнение — либо указать конкретный файл где задекларированы пункты меню, либо подтвердить что фича существует и указать её source.

> **Составлять test plan «по памяти» с придуманными названиями пунктов меню — запрещено** даже если исполнитель уверен что «примерно так выглядит». Ошибка на стадии (а) не исправляется на стадии (б) — исполнитель будет проверять то, чего нет.
