## TC-001 — Результат: BLOCKED

**Причина:** Evidence недостаточен для подтверждения визуального критерия.

---

### Анализ

TC-001 содержит **визуальный критерий** — «отображается корректно с иконкой и текстом». Согласно **Принципу 8** скила, для такого TC:

> a11y tree assertion **недостаточен** как единственный evidence — a11y tree не содержит визуальных свойств (цвет, стилизация, выравнивание, контраст). Обязательно: скриншот + открытие через Read + описание увиденного перед записью PASS.

Предоставленный evidence — `querySelector` вернул элемент — подтверждает лишь **существование элемента в DOM-модели**, но не его внешний вид. Это ещё слабее, чем a11y tree assertion: между DOM и рендерингом лежит CSS, который `querySelector` не видит.

**Фактически выполненная проверка:**
```
DOM: элемент найден в дереве ✓
```

**Требуемые проверки для PASS:**
```
1. Скриншот элемента → сохранён в reports/
2. Read скриншота → описание "вижу иконку X и текст Y"
3. a11y tree assertion из Snapshot (текстовое подтверждение, напр.:
   a11y: "ButtonIcon + 'Название кнопки'" found in toolbar region)
```

---

### Статус TC-001

| # | TC | Статус | Evidence |
|---|-----|--------|---------|
| 001 | Кнопка отображается корректно с иконкой и текстом | **BLOCKED** | querySelector вернул элемент — недостаточно для визуального критерия; скриншот не сделан, a11y tree не проверен |

---

### Что нужно для закрытия TC

1. Открыть приложение в браузере / через desktop-инструменты
2. Сделать скриншот кнопки → `reports/<ticket-id>-screenshot-TC001.png`
3. Открыть скриншот через `Read` и описать: видна ли иконка, читаем ли текст, нет ли overflow/обрезки
4. Зафиксировать a11y tree assertion из Snapshot с конкретным текстом элемента
5. Сверить с source-of-truth (конфиг/разметка компонента) — Принцип 10

Только после этого TC-001 может получить статус PASS или FAIL.
