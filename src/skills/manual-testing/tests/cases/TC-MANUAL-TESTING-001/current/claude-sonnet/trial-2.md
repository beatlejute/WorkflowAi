Согласно правилам скила:

**Инструмент:** Windows-MCP (desktop-инструменты)
**Среда:** Windows Sandbox (изолированная среда)

**Почему Sandbox обязателен:**
- Прямое тестирование на хосте загрязняет рабочую среду разработчика
- Sandbox воспроизводит чистое состояние (нет накопленных расширений, настроек, кэша)
- Изоляция гарантирует воспроизводимость тест-кейсов

**Следующие шаги перед началом:**

1. Загрузить `knowledge/desktop-tools-core.md` — команды Windows-MCP, паттерны навигации, бюджет Snapshot
2. Загрузить `knowledge/sandbox-core.md` — настройка Sandbox, quick-start, персистенция evidence
3. Проверить наличие `../shared/README.md` — там могут быть проектно-специфичные пути и конфигурация
4. Загрузить `algorithms/mcp-budget.md` — рассчитать бюджет MCP-сессии до начала тест-кейсов

**Стек проверки:** a11y tree (Snapshot) через Windows-MCP как основной evidence. Скриншоты — только для TC с визуальными критериями (принцип 8).

Чтобы начать работу — нужен конкретный QA-тикет с описанием что тестировать.
