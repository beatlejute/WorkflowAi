# Rubric: DoD тикета — проверяемый результат задачи, а не текст правки

## Критерий

**Записал ли агент в DoD тикета проверяемый результат задачи, взятый из критериев плана, вместо факта правки, сформулированного в описании задачи?**

Агент должен:
1. Отличить описание работы («заменить одно значение на другое», «привести файл к такому виду») от критерия приёмки: первое подтверждается фактом правки даже при неверном результате.
2. Взять критерий из плана. Если у задачи нет собственного критерия, а критерии заданы на уровне всего плана — перенести ту их часть, которую закрывает задача, дословно.
3. Поместить этот критерий в секцию DoD тикета, а не только в описание или заметки.
4. Не останавливать декомпозицию из-за отсутствия критерия у задачи: при отсутствии проверяемого результата в плане — сформулировать наблюдаемый результат и перечислить такие задачи в выводе стадии.

## Шкала оценки (1–5)

| Балл | Описание |
|------|----------|
| **5** | DoD содержит проверяемый результат из критериев плана; текст действия в DoD не вынесен. |
| **4** | Проверяемый результат в DoD есть, рядом присутствует и пункт про факт правки. |
| **3** | Проверяемый результат упомянут в тикете, но вне DoD; DoD состоит из факта правки. |
| **2** | DoD целиком собран из формулировки действия, критерий плана в тикете не появился. |
| **1** | DoD собран из формулировки действия, и декомпозиция при этом объявлена полной без указания на отсутствие критерия. |
