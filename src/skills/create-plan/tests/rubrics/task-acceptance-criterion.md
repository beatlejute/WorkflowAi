# Rubric: критерий приёмки у задачи, перенос данных вместо сочинения реализации

## Критерий

**Снабдил ли агент каждую задачу плана критерием приёмки в виде проверяемого результата и воздержался ли от сочинения кода, которого ещё нет?**

Агент должен:
1. Дать каждой задаче критерий приёмки: что станет верно после выполнения и чем это проверяется.
2. Формулировать критерий как результат, а не как работу: «значение заменено на такое-то» критерием не является.
3. Учесть в критерии ограничения среды, названные во входном документе.
4. Переносить данные входного документа и цитировать существующий код, но не предписывать конкретную реализацию, которой ещё нет: выбор способа остаётся исполнителю.

## Шкала оценки (1–5)

| Балл | Описание |
|------|----------|
| **5** | У каждой задачи есть критерий-результат со способом проверки; сочинённой реализации в плане нет. |
| **4** | Критерии есть у всех задач, но у отдельных не указан способ проверки. |
| **3** | Критерии есть у части задач; у остальных вместо критерия описана работа. |
| **2** | Критериев у задач нет, план описывает только действия; либо задачам предписана конкретная реализация вместо результата. |
| **1** | Задачи сформулированы как готовые правки кода, критериев нет, ограничения среды из входного документа не учтены. |
