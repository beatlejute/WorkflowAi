# Воркфлоу: выполнение и гейты

Фрагмент графа execute-task: этап 3 (выполнение) и этап 6 (гейты перед выводом). Вход — из
этапа 2 (контекст прочитан) и из этапа 4 (критерий не закрыт); выход — в этап 4 (верификация)
и в этап 7 (вывод). Подход определяется содержимым тикета — описанием и DoD, а не его типом.
Алгоритм выбора подхода и чеклист выполнения — `.workflow/src/skills/execute-task/algorithms/execution-strategy.md`.

## Антипаттерны

- Создание тикетов или планов в `.workflow/` — запрещено (узел P0R2)
- Создание тикета при обнаружении дефекта — дефект фиксируется в подразделе «Найденные дефекты» Result текущего тикета, рекомендация следующей задачи — в «Заметках» (узел P0R3)
- Перемещение тикета, запись `status` и `completed_at` — запрещено (узел P0R4)
- Работа без чтения контекстных файлов — приводит к неполному решению (узел P2S1)
- Завершение задачи без реального изменения файлов, если тикет требует изменения (узел P6S1)
- Призрачное выполнение — вывод RESULT при пустой секции Result или неотмеченных DoD (узлы P6S1, P7S2)
- Редактирование файла не по пути из `context.files` (узел P2R1)
- Вставка кода без понимания структуры (узел P3R4)
- Пропуск проверки существующего прогресса (узел P1R2)
- Отложенная запись результата вместо инкрементальной (узел P3R2)
- Заглушка на месте результата, который поручает описание тикета, если DoD этот результат не проверяет (узел P3R8)
- Тест против копии кода или симуляции вместо продукта, без утверждения о свойстве, с литералом вместо измерения, утверждение без первоисточника (узел P3R9)
- Прямой вызов API платформы мимо модуля проекта без записи выбора в Result (узел P3R4)
- Ослабление теста, починка дефекта вне scope, передача требования без чтения файла другого тикета (узлы P3S1, P3S2)
- Правка оборванной попытки, принятая за исходный код, и вывод команд в файлы проекта (узлы P1S2, P3R6, P6S3)
- Правка тикета на этапах 4 и 6 и ответ «да» на гейте при неисправленном пробеле (узлы P3R2, P4Q1, P6G1)
