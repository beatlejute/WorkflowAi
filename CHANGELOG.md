## [Unreleased]

### Changed
- **Судья тестов скилов — любой агент с командой, без отдельной ветки для модели.** В 1.10.0 судья на модели решений был безынструментным агентом `kind: http` со своей веткой в адаптере судьи, своим ключом в переменной окружения и кодом, который прятал этот ключ от остальных процессов. Теперь судья — только агент с командой: получает текстовый промпт и отвечает блоком `---RESULT---` со `score` и, если может, `confidence` и `cost_usd`. Судья `kind: http` отклоняется до прогона. Переоценка — полями записи любого судьи: `escalate_to` (кто переоценивает), `escalate_below` (порог уверенности; нет уверенности в ответе — переоценка), `escalation_share` (доля переоценки для оценки цены — замер, а не константа кода). Ответ без балла (`status: error`, `error_class`) — фоллбек на `escalate_to` с этим классом.
- **Модель решений — CLI-обёртка `src/scripts/decisions-judge.js`.** Получает тот же промпт судьи, берёт уровни из таблицы рубрики, спрашивает модель (OpenRouter `decisions`) и печатает балл — самый вероятный уровень — и уверенность. Модель, адрес и файл ключа — аргументы агента (`--model`, `--url`, `--key-file`, `--timeout`). Ключ — в файле, как у claude и kilo: в переменных окружения, которые наследуют все процессы, его нет.
- **Судья тестов всех скилов — Jev с переоценкой Opus.** `judge_agent: jev` в `tests/index.yaml` десяти скилов; запись `jev` в `configs/pipeline.yaml` — агент с командой (`decisions-judge.js`, `prompt_stdin: true`, ключ `~/.workflow/secrets/openrouter.key`), `escalate_to: claude-opus`, `escalate_below: 0.8`, `escalation_share: 0.292`. Основание — перемер 2026-09-26 на 284 оценках текущего прогона: совпадение pass/fail 94.7%, при пороге 0.8 на Opus уходит 29%, на оставшихся совпадение 100%, ни одно из 15 расхождений мимо порога не прошло; цена на тех же данных ≈ $18.5 против $63 у одного Opus. Нет файла ключа — все оценки даёт Opus.
- **Две рубрики manual-testing — шкалой-таблицей.** `artifact-prefix-reuse` и `qa-non-ui-assertion` держали уровни списком под «Проходной балл», и модель решений их не разбирала — оценку давал Opus. Тексты уровней те же, только с заглавной буквы, как в остальных рубриках; баллы в прозе (`FAIL, score 1-2`, `pass_threshold: 4`) убраны — баллы назначает только таблица. Тест рубрик требует таблицу уровней у всех рубрик канона.
- **Коуч: шкала — строками таблицы; нарушения в косвенно задетых файлах чинятся в той же правке.** В руководстве по авторству тестов правило «баллы назначает только таблица» уточнено: строка `| n | текст |` на каждый балл, иначе судья, отвечающий выбором уровня, рубрику не прочтёт. В черновике правки коуч исправляет нарушения своих правил и в файлах, которые правка задевает косвенно (коррекция стейкхолдера 2026-09-26: черновик оставлял две рубрики без таблицы). Регрессия — два anchors в TC-COACH-006.
- **Сравнение судей не сравнивает судью с самим собой.** `compare-judges.js` пропускает записи, балл которых дал сам `--judge`, и считает их отдельной строкой отчёта. Когда записи сделаны судьёй с переоценкой, перемер делает его `escalate_to`. Код выхода 1, если записи есть, а не сравнена ни одна — в том числе когда все с ошибкой судьи.

### Added
- **Ключ безынструментного агента из файла** — `auth: { file: <путь> }` (`~` — домашний каталог) рядом с `{ env }` и `{ kilo_oauth }`; нет файла или он пуст — `no_key`.
- **`prompt_stdin: true` у агента с командой** — промпт через stdin, а не последним аргументом (тесты скилов и стадии пайплайна): на Windows аргумент командной строки ограничен 32767 символами.

### Fixed
- **Агент, вышедший до чтения промпта из stdin, ронял весь раннер.** Запись промпта от 64 КБ в закрытый stdin даёт `EPIPE`/`EOF`, а обработчика ошибки у потока не было — необработанное исключение вместо отказа одного агента. Теперь это отказ агента с его кодом выхода (`agent-spawner.mjs`, стадии пайплайна в `runner.mjs`).
- **Адрес прокси или сервера в записи судьи.** В тексте сетевой ошибки адрес после системного вызова и кода (`connect E…`, `getaddrinfo E…` — при любом коде, IPv6 целиком) заменяется на `[address]`, имена и адреса сертификата после `altnames:` при TLS-отказе по имени — на `[redacted]` (`redactNetworkDetail` в `model-client.mjs`); запись судьи лежит в git.
- **Тесты на снятие записей судьи.** Повтор кейса с меньшим числом попыток и падение исполнителя до судьи — старые записи судьи снимаются; раньше это не проверял ни один тест.
- **Тест `--all --severity critical` читал реестр агентов из `.workflow/config/`** — копии установленной версии; теперь — из `configs/pipeline.yaml` репозитория.

## [1.10.0] — 2026-09-26

### Added
- **Судья тестов скилов — один контракт для двух видов судьи** (`src/lib/skill-judge.mjs`). CLI-агент (`claude-opus`) оценивает по текстовому промпту, как раньше, — промпт не изменился ни на байт. Безынструментный агент `kind: http`, `protocol: decisions` (модель решений Jev через OpenRouter) отвечает уровнем по таблице рубрики и уверенностью через слой оценки; состав его входа — как в пилоте 2026-09-24 (вывод исполнителя с файлами тикета, критерий кейса, пять уровней). Судья выбирается значением `judge_agent`, рубрики не трогаются. Судья по умолчанию во всех скилах остаётся `claude-opus`.
- **Эскалация и фоллбек судьи Jev.** Уверенность ниже `escalate_below` (по умолчанию 0.8) — попытку переоценивает `escalate_to` (CLI-агент), итог — его балл, ответ Jev остаётся в записи. На пилоте при пороге 0.8 мимо эскалации прошли 2 расхождения с Opus из 18. Любая ошибка клиента (нет ключа, 401, 5xx, таймаут, чужой ответ) и рубрика без таблицы уровней тоже уходят к `escalate_to` с пометкой `fallback: <класс>`: сбой сети не валит прогон. Без ключа — одно предупреждение на прогон, оценка цены перед прогоном — по `escalate_to`. Судья `kind: http` без `escalate_to` на CLI-агента, с `protocol: chat` или с адресом не `https://` отклоняется до прогона. Таймаут вызова — `execution.judge_timeout_s` скила, как у CLI-судьи. Клиент судьи берёт окружение со слоем `~/.workflow/agent.env` (ключ, прокси), как стадии `model_io`.
- **Ключ судьи не уходит исполнителям кейсов.** Исполнители наследуют окружение раннера целиком, в том числе бесплатные модели сторонних провайдеров. Раннер тестов снимает переменные `auth.env` безынструментных агентов со своего окружения до первого запуска исполнителя; клиент судьи получает снимок, сделанный до этого.
- **Слой оценки отдаёт ответ модели как есть** — поле `raw` (`answers` провайдера для decisions, текст для chat). Его сохраняет запись вызова судьи.
- **Запись вызова судьи по каждой попытке** — `current/<agent>/trial-<N>.judge.json` рядом с выводом исполнителя: вход, промпт, сырой ответ, балл, уверенность и вероятности, эскалация или фоллбек, длительность, цена, ошибка. Пишется и при ошибке судьи; записи попыток, которых в прогоне нет, снимаются; адрес сервера в тексте ошибки клиента заменяется на `[host:port]`. `judge.json` и `meta.json` прежней формы.
- **Сравнение судей по записям** — `src/scripts/compare-judges.js --judge <агент>`: переоценивает записи другим судьёй без запуска исполнителей и выдаёт совпадение (точное, ±1, pass/fail), матрицу 5×5, разбивку по скилам, таблицу порогов уверенности 0.7/0.8/0.95 и цену; расхождения — по файлу на случай (`--disagreements`). Перед вызовами — оценка и вопрос (`--yes` пропускает). Балл записи, который дал `escalate_to`, приписывается ему. Ни одна запись не переоценена — код выхода 1.
- **Конвертер шкалы рубрики** (`src/lib/rubric-levels.mjs`): пять текстов уровней из таблицы `| 1 | … |`…`| 5 | … |`, заголовок не важен. Разбирает 40 рубрик канона из 42; две рубрики manual-testing держат уровни списком и дают ошибку с именем файла.
- **Агент `jev` в `configs/pipeline.yaml`** — судья тестов скилов (`typesafe/jev-1.13`, ключ `OPENROUTER_API_KEY`, эскалация на `claude-opus` ниже 0.8). Исполнителем и судьёй скилов не назначен.

### Changed
- **Цена судьи в оценке перед прогоном — из записи агента.** `cost_per_call` судьи (у `claude-opus` — $0.222, замер 207 вызовов 2026-09-22); у Jev с эскалацией — плюс доля эскалации пилота (0.284) × цена `escalate_to`. Прежняя константа $0.02 была в 11 раз ниже замера; без поля она остаётся, с предупреждением «цена судьи не задана». Строка оценки показывает долю судьи.

### Fixed
- **Ответ судьи без балла был тройкой.** Раннер ставил `score: 3` до разбора ответа: сломанный ответ судьи был неотличим от честной тройки. Теперь ответ без `score: <1-5>` и балл вне 1..5 — ошибка попытки (`errored`, `error: judge: judge output unparsed`); калибровка с таким ответом останавливается с причиной, а не «miscalibrated».

## [1.9.0] — 2026-09-26

### Changed
- **Ответ без единого вызова инструмента на скиле с рельсами — нарушение.** Хук рельс создаёт состояние сессии на первом вызове инструмента; агент, который ни одного не сделал, отвечал без процедуры скила, и output-check его не проверял — ни в пайплайне, ни в тестах скилов. Прогон deep-research 2026-09-25: gpt-luna во всех трёх попытках выдала отчёт без единого вызова инструмента, одна попытка прошла. Теперь, если хуки рельс для агента на месте (kilo — загрузчик плагина в каталоге агента и ядро рельс, claude — хуки в настройках пользователя или проекта со скриптом на месте), такой ответ уходит на повтор с вердиктом: пройти граф с `node .workflow/src/rails/cli.mjs start <skill>`, финальный ответ — только в терминальном узле. В тестах скилов повтор снова без вызовов — попытка не проходит при любой оценке судьи (`rails_failed` в `meta.json`, «провалено без рельс» в `rails_warnings`); в пайплайне — предупреждение в логе стадии. Хост рельс определяется по команде агента (`kilo … run`, `claude`) или полем `rails_host: kilo|claude` в записи агента — для обёртки с другим именем; другое значение — ошибка конфига при старте.
- **Коуч при переводе скила на рельсы сверяет тексты заданий тестов с графом.** Новый шаг перевода: задание кейса не запрещает вызовы инструментов вообще и не велит отвечать по памяти — без единого вызова рельсы не включаются. Точечный запрет (например, веб-поиска) остаётся с прямой строкой «процедуру проходи по графу командами rails». Прогон deep-research 2026-09-25: задание «поиск недоступен, работай с тем, что знаешь из контекста» после перевода не пересмотрели, и gpt-luna ответила без единого вызова во всех трёх попытках. Задание этого кейса переписано: недоступен только веб-поиск, граф проходится командами rails.
- **deep-research: суррогат источника определён критерием.** Суррогат — любая пометка на месте URL, а не только «требует верификации»: «требует проверки», уровень уверенности или название источника без URL, «общее знание». Прогон 2026-09-26: три попытки на рельсах закрыли так факты и не прошли оценку. Гард выходного слоя по-прежнему ловит только «требует верификации» — его правка в `rails.yaml` остаётся за человеком.
- **Отказ рельс и вывод `start`/`goto` дают готовую команду перехода.** Каждый допустимый переход — строкой `id: лейбл → node .workflow/src/rails/cli.mjs goto <id> --quote '<цитата>'`; цитату `goto` принимает как есть (проверено на всех переходах графов канона). Вердикт повтора по output-check называет узел, где агент числится, и те же команды. Прогон deep-research 2026-09-25: haiku после отказа писала «пройду граф правильно» и снова не делала ни одного перехода — отказ называл узлы, но не команду.

### Fixed
- **Рельсы на Linux и macOS принимали путь PowerShell с `\` за имя файла.** pwsh на POSIX считает `\` разделителем: `Remove-Item ..\..\x` удаляет файл двумя каталогами выше (проверено на pwsh 7.6.6, Linux). Детектор записи читал `..\..\x` как имя файла в текущем каталоге, и запись вне области выглядела записью внутри. Теперь в PowerShell на POSIX `\` — разделитель, как `/`.
- **Рельсы на POSIX не разбирали `powershell.exe` и `cmd.exe`.** В WSL программы Windows запускаются по имени с `.exe`, регистр не важен. Детектор узнавал вложенный интерпретатор только по имени без расширения, и `decide` разрешал `powershell.exe -Command "Remove-Item <вне области>"`. Теперь `.exe` на POSIX отбрасывается, как на Windows.
- **Сканер секретов в фикстурах падал без `.workflow/`** даже с абсолютным `--path`: корень проекта искался при импорте, и вывода `---RESULT---` не было. Теперь корень ищется только для путей по умолчанию и относительного `--path`.
- **CI доходит до конца на всех ОС.** После починки тестов CI упёрся в храповик покрытия: восемь порогов базы были сняты на Windows с Node 25 и оказались выше замера на Node 22, на котором идёт CI (на Linux и macOS, у `agent-spawner.mjs` — и на Windows). Они опущены до минимума трёх замеров на Node 22 (Windows, Linux, Linux с временным каталогом через ссылку, как на macOS); остальные пороги не менялись. Тест уборки каталога преднагрузки считал утечкой живой каталог соседнего файла набора — теперь дочерний прогон получает свой временный каталог. Сканер секретов покрыт тестами пути по умолчанию и относительного `--path`.
- **Тесты не завязаны на Windows и на форму временного каталога.** Прежде CI падал на всех трёх ОС, и публикация по метке версии не доходила до npm. Проверки, завязанные на Windows (замена занятого файла, путь `kilo.cmd`), идут только там или берут путь своей ОС; временные каталоги берутся в полной форме (`/var` → `/private/var` на macOS, `RUNNER~1` на Windows); проверка лестницы повторов считает попытки, а не миллисекунды.

## [1.8.1] — 2026-09-25

### Changed
- **deep-research переведён на рельсы.** Процедура — граф: ядро (вход и правила, синтез и отчёт с валидацией, self-check, выдача результата) и шесть веток по типам исследования, у каждой ветки — гейт дополнительной проверки. Гарды: запись в каталог скилов закрыта (прогон 2026-09-25: отчёт писался в каталог скила), выдача результата и остановка — один терминальный узел, суррогат «требует верификации» в финальном ответе отклоняется, у каждого гейта потолок повторов. Отчёт кладётся по пути из тикета, а не в `reports/`. Правило «исследование только через perplexity-research.js» гардом не принуждается: рельсы не сопоставляют веб-инструменты по этапу.

### Fixed
- **Kilo-агенты тестов скилов работали в настоящем проекте, а не в песочнице.** `kilo run` 7.7.x берёт каталог проекта из `PWD`, а раннер, запущенный из Git Bash, передавал агенту `PWD` каталога запуска вместе с `cwd` песочницы. Агенты читали файлы настоящего проекта, состояние рельс писалось туда же, раннер не находил его в песочнице и молча не выполнял output-check (прогоны 2026-09-23 и 2026-09-25). Теперь `PWD` агента — его рабочий каталог, в тестах скилов и в пайплайне.
- **Тест скила на рельсах сообщает, что рельсы не зацепились.** Попытка без состояния сессии в песочнице (и повтор по output-check — по его собственному запуску) даёт предупреждение `⚠ rails` в выводе, строку `rails_warnings` в блоке ---RESULT--- (в режиме `--all` — с именем скила) и счётчики `rails_not_engaged` / `rails_escaped` по модели в `meta.json`. Предупреждение называет факт — где состояния нет или где оно нашлось; `rails_escaped` — агент работал мимо песочницы. Раньше такая попытка проходила молча — модель без единого вызова инструмента получала высший балл без принуждения рельс.
- **Улики рельс прошлого прогона оставались рядом с новым.** Попытка без журнала и состояния рельс не трогала `rails-trial-N.jsonl` и `rails-state-trial-N.json` прошлого прогона, и они читались как улики текущего. Теперь раннер снимает их перед сохранением новых.
- **Проверка полноты плана больше не считает пустой каждую секцию.** `validate-completeness.js` смотрел только на строку сразу после заголовка и выдавал «Пустая секция» на любой заголовок с пустой строкой после него — на PLAN-002 это 59 предупреждений. Теперь секция пуста, только если до следующего заголовка того же или старшего уровня в ней нет содержания. Подсекции считаются содержанием, подсказка шаблона `<!-- … -->` — нет, `#` во frontmatter и в блоках кода заголовком не считается.

## [1.8.0] — 2026-09-25

### Added
- **Безынструментные агенты (`kind: http`).** Модель, которая не пользуется инструментами, подключается записью в `pipeline.agents`, без правок кода: `kind: http`, `protocol` (`chat` или `decisions`), `url` (`https://`; `http://` — только localhost, 127.0.0.1, ::1), `model`, `auth` (`{ env: <ИМЯ> }` или `{ kilo_oauth: true }`), `timeout_s` (на одну попытку). Протокол `chat` — формат OpenAI chat completions без `tools`, с изображениями (PNG, JPEG, WebP; до 5 МБ, до 8 на запрос); `decisions` — типизированная оценка OpenRouter. Общий клиент — `src/lib/model-client.mjs`: ключ только из переменной окружения или токена kilo (на Windows имя переменной — без учёта регистра), прокси из `HTTPS_PROXY` и соседних переменных (туннель CONNECT), до двух повторов на 429/500/502/503 и сетевую ошибку, прерывание через `AbortSignal`, классы ошибок `no_key`, `auth`, `rate_limit`, `server`, `timeout`, `network`, `bad_request`, `bad_response`, `aborted`.
- **Слой оценки** (`src/lib/model-evaluate.mjs`): вопросы с уровнями на входе, уровень 1..n по каждому вопросу на выходе — одинаково для обоих протоколов.
- **Обмен стадии с моделью (`model_io`).** Стадия с `model_io: { prepare, apply, options }` исполняется агентом `kind: http` в три шага: скрипт prepare собирает вопросы, раннер спрашивает модель через слой оценки и пишет ответ в `.workflow/state/model-io/<стадия>-<run_id>-<id вызова>.json`, скрипт apply выдаёт статус стадии. Ошибка модели — `status: error` с `error_class` (нарушение контракта prepare — `bad_prepare`), в истории работы тикета — `error`; остановка пайплайна снимает запрос к модели и не запускает apply (`aborted`); `auth`, `rate_limit`, `server`, `timeout`, `network` помечают агента в health-реестре и передают стадию следующему агенту. В лог пишется строка `MODEL_IO` с моделью, длительностью шагов и `cost_usd`. Модель стадии выбирается по `required_capabilities`: для изображений — агент с `multimodal`.
- **Защита от ошибочного назначения.** Проверка конфига при старте отклоняет агента `kind: http` в стадии без `model_io` (`agent`, `agents`, `agents_by_type`) и в `default_agents`/`default_agent`, а также неполную или противоречивую запись агента и `model_io` со ссылкой на несуществующий скрипт. Тесты скилов не берут такого агента исполнителем (`target_agents`, `--agent`); судьёй он допустим.
- **Причина ошибки в выводе тестов скилов.** `run-skill-tests.js` со `status: error` печатает строку `error: …`.

### Fixed
- **Остановка пайплайна передавала стадию следующему агенту.** Агент, убитый по SIGINT/SIGTERM, выглядел как обычный сбой: при пустом diff артефактов `executeWithFallback` запускал следующего агента списка уже после запроса на остановку, а убитый агент мог попасть в health-реестр. ### New Features
- **New built-in stage type: `manual-gate`** — Adds support for manual approval steps in pipelines. When a stage with `type: manual-gate` is encountered, the runner creates a pending approval file in `.workflow/approvals/{step_id}.json` and enters a polling loop, waiting for an external decision (`approved`/`rejected`).

  **Key capabilities:**
  - Deterministic `step_id` generation: `{ticket_id}_{stageId}_{attempt}` (e.g., `QA-12_manual-approve_0`)
  - Idempotent file creation — pending file is not overwritten on retry/restart
  - Configurable polling interval (`poll_interval_ms`, default 2000ms) and optional timeout (`timeout_seconds`)
  - Graceful handling of SIGTERM/runner stop (returns `aborted`)
  - Immediate return if file already has `approved`/`rejected` status (crash recovery)
  - JSON approval file format with full audit trail (`created_at`, `updated_at`, `decided_by`, `comment`, `context_snapshot`)

  **Pipeline configuration example:**
  ```yaml
  stages:
    manual-approve-deploy:
      type: manual-gate
      poll_interval_ms: 2000
      timeout_seconds: 86400
      goto:
        approved: continue-deploy
        rejected: rollback
        timeout: notify-stuck
        aborted: end
  ```

  **Two approval methods (both opt-in):**
  1. **External MCP/client**: tools like `workflow-mcp` can write to approval files programmatically
  2. **Direct file edit**: users can simply edit `.workflow/approvals/{step_id}.json` and change `status` to `approved` or `rejected`

  **Important:** `manual-gate` is **opt-in** — pipelines without such stages work identically to previous versions. No breaking changes.
