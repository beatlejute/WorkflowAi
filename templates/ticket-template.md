<!--
Пункт — дословный текст критерия приёмки из плана. Под ним — вложенная
проверка ровно одной формы; ключи латиницей, значения в обратных кавычках,
пары через запятую:
- check: `<команда>`, expect: `<ожидание>` — одна команда без операторов
  оболочки (; && || | > < ` $( ), запуск от корня проекта. Разрешены node,
  npm (test, run <скрипт>), git (status, diff, log, show, ls-files, rev-parse,
  grep), pytest, python, dotnet, rg, grep. Исполняемый файл должен быть на
  машине, где идёт пайплайн: проверку без него отклоняют валидатор плана и гейт
  перед работой. rg и grep установлены не везде — текст в репозитории ищет
  `git grep -q --untracked "<текст>" -- <путь>` (без --untracked новый файл не
  виден, пока его не добавят в git); путь, который игнорирует git
  (`git check-ignore -q <путь>` даёт exit 0), — только с --no-exclude-standard:
  `git grep -q --untracked --no-exclude-standard "<текст>" -- <путь>`, без него
  поиск такой файл не видит. Ожидание: `exit <N>` |
  `stdout contains <текст>` | `stdout not contains <текст>` |
  `stdout matches /<регэксп>/`. Закрывает скрипт, без модели. Команда
  укладывается в таймаут исполнителя проверок — 120 с, дольше она прерывается,
  и пункт красный при любой работе. Аргументы скрипту npm — после `--`.
  Ожидание по тексту вывода — только сверенному запуском: итоговая строка
  отчёта многих инструментов печатает только ненулевые счётчики.
- regression: `true` после check и expect — проверка зелёная и до работы:
  прогон существующего теста или `npm test`. Хотя бы один пункт тикета —
  другого вида: check без пометки, prose или visual. Гейт перед работой такую
  проверку не запускает — её исполняет только ревью.
- prose: `<почему командой не проверить>` — непустая причина; оценивает модель
  стадии ревью по собранным evidence.
- visual: `<путь или маска>` — изображения PNG, JPEG или WebP от корня
  проекта; кладёт исполнитель тикета, оценивает агент ревью со способностью
  multimodal.

Проверку проходит правильно сделанная работа этого тикета — при любом состоянии
того, что тикет не меняет:
- тикет тестирования (qa) проверяет сценарий и записывает фактический результат;
  найденный дефект — выполненный пункт. Его check подтверждает, что сценарий
  проведён и фактические значения записаны в артефакт (поля есть и заполнены), а
  не что продукт прошёл. Правильность продукта — критерий тикета, который продукт
  меняет. 2026-09-28: check тикета тестирования проходил только на исправленном

  результат (например, запись митигации читает отчёт тикета исследования).
  2026-09-28: `git status` каталога тестов с ожиданием «нет новых файлов»
  проваливали файлы соседних тикетов, исполнители трёх моделей;
- prose оценивает модель, которая видит только evidence: вывод проверок пунктов,

  доски тикетов и прогонов тестов в evidence нет. Сверку с ними делает check.
