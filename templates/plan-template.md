<!-- 
Каждая задача будет декомпозирована Administrator'ом на тикеты.
Указывайте приоритет и зависимости.

Критерий приёмки — что станет верно после выполнения задачи. После
**Проверка:** — чем это проверяется: одна запись в той же строке или несколько
вложенным списком. Утверждения критерия, которые доказывают разные записи, —
каждое своей строкой **Критерий приёмки:** со своей **Проверка:** (задача 2);
запись check доказывает утверждение, если красная, пока оно не выполнено.
Каждая запись при декомпозиции становится проверкой одного пункта DoD тикета
с полным текстом своего критерия. Ключи латиницей, значения в обратных кавычках, пары через
запятую; у записи ровно одна форма:
- check: `<команда>`, expect: `<ожидание>` — одна команда без операторов
  оболочки (; && || | > < ` $( ), запуск от корня проекта. Разрешены node,
  npm (test, run <скрипт>), git (status, diff, log, show, ls-files, rev-parse,
  grep), pytest, python, dotnet, rg, grep. Исполняемый файл должен быть на
  машине, где идёт пайплайн: проверку без него отклоняют валидатор плана и гейт
  перед работой. rg и grep установлены не везде — текст в репозитории ищет
  `git grep -q --untracked "<текст>" -- <путь>` (без --untracked новый файл не
  виден, пока его не добавят в git); все строки набора в одном файле —
  `git grep -q --untracked --all-match -e "<текст1>" -e "<текст2>" -- <файл>`.
  Ожидание: `exit <N>` |
  `stdout contains <текст>` | `stdout not contains <текст>` |
  `stdout matches /<регэксп>/`. Закрывает скрипт, без модели. Команда
  укладывается в таймаут исполнителя проверок — 120 с, дольше она прерывается,
  и пункт красный при любой работе. Аргументы скрипту npm — после `--`.
  Ожидание по тексту вывода — только сверенному запуском: итоговая строка
  отчёта многих инструментов печатает только ненулевые счётчики.
- check: …, expect: …, regression: `true` — регрессионный прогон существующего
  теста или `npm test`: зелёный и до работы. О результате задачи такая запись
  не говорит — у задачи нужна и запись другой формы. Гейт перед работой запись с
  regression не запускает — её исполняет только ревью. Запись check без
  regression красная на дереве, где задачи-зависимости выполнены, а эта задача
  нет: перед стартом пайплайн исполняет её, и зелёная отправляет тикет в blocked/.
- prose: `<почему командой не проверить>` — непустая причина; модель стадии
  ревью оценивает по собранным evidence текст критерия, причину она не видит.
- visual: `<путь или маска>` — изображения PNG, JPEG или WebP от корня
  проекта; кладёт исполнитель тикета, оценивает агент ревью со способностью
  multimodal.

Проверку проходит правильно сделанная задача — при любом состоянии того, что
